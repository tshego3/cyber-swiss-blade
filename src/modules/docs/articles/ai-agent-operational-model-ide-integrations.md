# AI agent IDE integrations

This article tells how to use the AI agents in the IDEs and SQL tools. Use Copilot for inline completions and chat, Claude Code for multi-file agentic work, and Ollama with Continue for offline or private work. It is part of the [local and hybrid AI agent operational model](doc:ai-agent-operational-model).

## Before you start

- Install the tools in [AI agent setup and installation](doc:ai-agent-operational-model-setup).
- The Claude Code VS Code extension needs a current VS Code release and Node.js 18 or later.
- Copilot BYOM needs an active Copilot subscription.

## Claude Code in VS Code

Claude Code is the recommended tool for agentic workflows. It edits files, runs terminal commands, and does Git operations in the workspace.

### Install the extension

1. Install **Claude Code** from the VS Code Marketplace. If the CLI is not installed, the extension installs it at the first start.
2. To install the CLI yourself, use the per-user install script (recommended on a locked-down Windows device), or `npm install -g @anthropic-ai/claude-code`.
3. Sign in with `claude` (browser OAuth), or set `ANTHROPIC_API_KEY`.

### CLI commands for advanced users

| Task | Command |
| --- | --- |
| Interactive session | Run `claude` in the project root. |
| One prompt | `claude -p "prompt"` |
| Piped input | `dotnet build 2>&1 \| claude -p "Fix the first compiler error"` |
| Session control | `claude --continue`, `claude --resume` |
| Commands in a session | `/model`, `/clear`, `/compact`, `/agents`, `/mcp`, `/init`, `/cost` |
| MCP management | `claude mcp add`, `claude mcp list` |
| Health check and update | `claude doctor`, `claude update` |

### Use Claude Code in VS Code

| Action | How |
| --- | --- |
| Open the Claude Code panel | Use the sidebar or the Command Palette (`Ctrl+Shift+P`). |
| Open or focus Claude Code | `Ctrl+Esc` |
| Change between plan mode and auto-accept mode | `Shift+Tab` |
| Stop the agent during a response | `Esc` |

Diffs open in the VS Code diff viewer. Review them before you accept them.

### Give context

- Claude Code reads the current editor selection and the open tabs as context.
- Refer to files exactly in the prompt: `Refactor @Components/Pages/Login.razor to use the AuthService pattern from @Services/AuthService.cs`.
- Refer to a line range in the prompt text, for example "lines 15-45 of Login.razor".

### Project memory

Run `/init` to generate a `CLAUDE.md` file at the repository root. Keep the rules that repeat in `CLAUDE.md`. Keep harness settings in `.claude/settings.json`.

## Configure a Claude Code project

Put a `CLAUDE.md` file and a `.claude/` folder at the repository root. They configure the behavior for each project.

| File or folder | Contents |
| --- | --- |
| `CLAUDE.md` | Generated by `/init`. Build commands, architecture notes, coding standards, and forbidden patterns. Claude Code loads it in every session. |
| `.claude/settings.json` | Project settings. Commit it to Git. |
| `.claude/settings.local.json` | Personal overrides. Add it to `.gitignore`. |
| `.claude/agents/` | Custom subagent definitions (for example `code-reviewer.md`, `sql-expert.md`). |
| `.claude/commands/` | Reusable slash commands, as Markdown prompt files. |
| `.mcp.json` | Project-scoped MCP servers that the team shares. |

Example `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "Bash(dotnet build:*)",
      "Bash(dotnet test:*)",
      "Bash(git status)"
    ],
    "deny": ["Read(./.env)"]
  },
  "model": "claude-sonnet-5"
}
```

> **NOTE:** Verify the model ID `claude-sonnet-5` against the current Claude model list before you use it. You can also use an alias such as `sonnet`.

## Claude Code in Visual Studio

Claude Code is a CLI tool. It has no native plugin for the full Visual Studio IDE. Use the integrated terminal.

1. Open the terminal (`View` > `Terminal`).
2. Run `claude` to start the interactive session.
3. Let the agent edit files and run build commands (`dotnet build`, `dotnet test`) in the Visual Studio project context.
4. After the agent edits project files, reload the solution. The IDE then sees the changes.

Use **GitHub Copilot** in Visual Studio for inline completions and chat. Use Claude Code in the terminal for multi-file agentic work.

For X++, AL, and Dataverse, read [Dynamics 365 development with Claude Code](doc:ai-agent-operational-model-dynamics-365).

## SQL Server tools

### SSMS with a file-based workflow

SSMS does not support agentic plugins such as Claude Code. Use a file-based workflow:

1. **Development:** Use Claude Code in a separate terminal to plan and generate `.sql` scripts in the project folder.
2. **Execution:** Open the generated `.sql` files in SSMS. Run and verify them against the database.
3. **Feedback:** Copy execution errors or query plan problems from SSMS. Paste them into Claude Code to refine the scripts.

For automated verification, let Claude Code run `sqlcmd` or `Invoke-Sqlcmd` in the terminal. It can then run scripts and validate results in the CLI.

### VS Code as the SQL Server interface

SSMS has no alternative AI support. For better productivity, move database development into VS Code and use it as the AI interface for SQL Server.

Extensions:

| Extension | Use |
| --- | --- |
| SQL Server (mssql) | Connectivity, query execution, and IntelliSense for T-SQL |
| SQL Database Projects | Project-based database development: schema as code and dacpac deployments |

AI tools:

- **GitHub Copilot:** Real-time T-SQL autocomplete and natural-language query generation.
- **Claude Code:** The orchestrator for complex database migrations, index optimization plans, and schema refactoring.

Set up the environment:

1. Install VS Code and the `mssql` and `SQL Database Projects` extensions.
2. Create a connection profile to the target SQL Server instance.
3. Create a new **SQL Database Project** (`Ctrl+Shift+P` > `SQL Database Projects: Create New`). Git can then track the schema changes.
4. Keep a `CLAUDE.md` file in the root. The agent reads the project structure from it and generates valid T-SQL scripts.

Development workflow:

1. **Plan:** Use Claude Code to break up a database change (for example "Add audit columns to all transaction tables").
2. **Generate:** Claude Code writes the `.sql` scripts into the project folder.
3. **Verify:** Use the `mssql` extension to run the script against a development instance.
4. **Deploy:** Use the database project to publish the changes to the target environments.

### Azure Data Studio

Azure Data Studio is the recommended alternative to SSMS for an integrated, Copilot-like experience with SQL Server. It uses the VS Code engine, so it supports the **GitHub Copilot** extension and other VS Code-compatible AI plugins. It gives T-SQL autocomplete, chat-based query generation, and an integrated terminal for Claude Code.

> **NOTE:** Dated (checked November 2026): Microsoft retired Azure Data Studio on February 28, 2026. Use VS Code with the `mssql` extension, as in [VS Code as the SQL Server interface](#vs-code-as-the-sql-server-interface).

## Continue (open-source AI agent)

1. Install **Continue** from the VS Code Marketplace.
2. Edit `config.yaml`. Set the roles (`chat`, `edit`, `apply`, `embed`, `rerank`) and the context providers (`codebase`, `tree`, `problems`, `terminal`, `repo-map`, `debugger`).
3. Turn on codebase indexing: set "Enable" in the Indexing settings. To index again, use `@codebase index`.

More features:

- **Inline autocomplete:** Turn it on in the settings and set the provider to a local Ollama model.
- **Git commit messages:** Use `@Git Diff` in the chat to generate short commit summaries.

## GitHub Copilot Pro and M365

### Licensing

- **Copilot Pro:** Completions, chat, and agent mode.
- **M365 Copilot:** The Pro features and integration into the M365 applications.

### Features

| Feature | Use |
| --- | --- |
| Inline completions | Ghost text. Press `Tab` to accept it. |
| Copilot Chat (`Ctrl+Alt+I`) | Workspace-scoped queries and image attachments. Use the `@workspace` participant to give full workspace context. |
| Agent mode | Select **Agent** in the chat mode picker. Full project context for multi-file generation. |
| Copilot Edits (`Ctrl+Shift+I`) | Multi-file editing with review and accept cycles. |
| Custom instructions | Put project rules in `.github/copilot-instructions.md`, for example naming conventions, architecture constraints, forbidden patterns, "SSR only", or "No inline styles". |

> **NOTE:** Dated (checked November 2026): VS Code merged Copilot Edits into the Chat view in 2025. Use the **Agent** or **Edit** mode in the chat mode picker for multi-file edits. `Ctrl+Shift+I` now opens the Chat view in agent mode.

### Bring your own model (BYOM)

Copilot BYOM needs an active Copilot subscription. Use the **OpenAI Compatible** option in the Language Model settings to connect Copilot to local endpoints.

## Workspace optimization

- In `settings.json`, turn on `editor.inlineSuggest.enabled`.
- Make sure that `search.exclude` has `bin/`, `obj/`, and `*.Designer.cs`. This prevents indexing noise.
- Commit after each verified task, for example `git commit -m "step-N: [description]"`. This gives small diffs that are easy to review and easy to roll back.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| The extension cannot start the Claude Code CLI | Make sure that `claude` is on the PATH. Then reload the VS Code window. |
| Authentication loops | Run `claude` in a terminal and sign in one time. Then reload VS Code. |
| A permission prompt for each command | Add trusted commands to `permissions.allow` in `.claude/settings.json`. |
| Continue shows `lance.connect` errors on macOS ARM64 | Run `npm install @lancedb/vectordb-darwin-arm64` in the extension folder. |
